# MySQL Shell Quick Reference

## Connecting (do this first, every session)

The one-liner that avoids every gotcha from tonight — connects **and**
selects your schema in one shot:

```
\connect root@localhost:3306/Matchmaking
```

- Enter your root password when prompted.
- If it asks "Save password?" — `N` is fine unless you want to skip
  typing it next time (saves it to your OS credential store).

If you ever just run `\connect root@localhost` (no port, no schema),
you'll connect fine but get `No database selected` on your first
query — just run `USE Matchmaking;` right after to fix it.

## Mode switching

MySQL Shell opens in **JavaScript mode** by default — SQL statements
will fail with a syntax error until you switch.

| Command | What it does |
|---|---|
| `\sql` | Switch to SQL mode (do this if `SHOW TABLES;` gives a syntax error) |
| `\js` | Switch to JavaScript mode (Shell's default — you probably won't need this) |

## Everyday session commands

| Command | What it does |
|---|---|
| `\connect root@localhost:3306/Matchmaking` | Connect and select your schema in one step |
| `\disconnect` | Close the current connection without quitting the Shell |
| `\quit` or `\exit` | Close MySQL Shell entirely |
| `USE Matchmaking;` | Select the schema manually (needed if you connected without `/Matchmaking`) |
| `SHOW DATABASES;` | List all schemas on the server |
| `SHOW TABLES;` | List tables in the currently selected schema |
| `DESCRIBE table_name;` | Show a table's columns, types, and constraints |

## If something feels broken

| Symptom | Likely cause | Fix |
|---|---|---|
| `Expected ; but found ...` (SyntaxError) | You're in JS mode, not SQL mode | Run `\sql` |
| `ERROR: Not connected.` | You switched modes but never connected this session | Run `\connect root@localhost:3306/Matchmaking` |
| `ERROR: 1046: No database selected` | You connected without specifying a schema | Run `USE Matchmaking;` |
| `Access denied for user 'root'@'localhost' (using password: NO)` | Happens in Python — usually means your `.env` file wasn't found or `DB_PASSWORD` didn't load | Check `.env` is in the same folder as your script and named exactly `.env` (not `.env.txt`) |
| Everything hangs / nothing connects at all | MySQL service isn't running (common after a PC restart) | Open **Services** (Windows key → search), find `MySQL80`, confirm it says **Running** — start it if not |

## Prefer a GUI instead?

MySQL Workbench (already installed alongside MySQL Shell) skips all
of this — open it, double-click your saved local connection, and
you're dropped straight into a connected SQL editor. Good option if
the Shell's connect/mode dance ever gets annoying mid-session.
